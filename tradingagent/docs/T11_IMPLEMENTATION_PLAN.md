# T11建议编排实施细化

按用户既有授权自主实施。T03预算、T07硬纪律、T08调度和T09只读缓存是前置基础。
供应商、价格、日预算均未由用户配置；首轮只用Fake/录制响应，不调用收费端点。

## 顺序与裁决

1. 先实现路由与费用估计的严格配置/测试。默认规则、日预算0、没有模型/价格版本关闭收费。普通解释economy、明确复杂变化standard、复盘review；不由模型选择升级。
2. 构建有限Prompt投影，剔除account_ref/订单ID/凭据/完整日志。输入金额字符串、原始风格/版本、有限已知证据、缺失项；用户文本和Provider输出作为非可信数据。
3. 每次模型请求前持久预留，费用使用保守输入上界和最大输出token。每个回退单独预留，最多一次；手工/复盘共享T03小时额度。未知费用/超时/取消保留预留；实际超估使用已有冻结机制。
4. 严格解析action/source/evidence/数量/期限及usage身份；非法JSON/未知字段/伪造证据不发布。正式HTTP Adapter在用户确定供应商和配置前保持关闭。
5. 构建可恢复请求台账与发布Port。相同request_id不重复调用；先记immutable snapshot/创建状态，审计成功后才能发布。崩溃留下in-flight不自动重复收费。
6. 发布时在同一存储事务核对session/style与账户实质revision；当前行情/风险在发布前再次评估。仅独立读后普通save会留下竞争窗口，因此增加明确的原子发布接口与回归测试。
7. 风格/账户变化保留原建议为SUPERSEDED；过期/数据缺失/预算失败为UNAVAILABLE。不改原始作者、快照或证据时间。免费规则和Fake也须防重复发布。
8. 接入运行中的scheduler与Web建议投影，不新增交易能力；Fake集成、故障/并发/重启/预算日切、独立审查与完整验证后记录。

模型层故障不能关闭行情/账户采样，硬风险提示不等待LLM。供应商、模型、有效价格版本/日预算及真实凭据未配置时，不以占位模型伪装可用。
JEV继续未定义；测试规则阈值不当作经验证策略。建议数量缺少用户纪律或费用证据时保持为空或被风险拒绝。
