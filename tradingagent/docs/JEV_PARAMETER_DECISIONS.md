# JEV 合约参数决策 v2

状态：2026-10-08 代码与离线验收完成。当前8776旧服务未重启，旧钱包保持固定金额模式，v2尚未收费实测。

## 需求与当前差距

自动操盘需要模型选择具体的仓位和杠杆。现有 v1 只有 OPEN_LONG / OPEN_SHORT / REDUCE / WAIT，开仓固定名义金额、杠杆固定，REDUCE 实际全平。用户确认：首次开仓按账户净权益的保证金比例，加仓/减仓按当前合约数量比例。

## 协议

采用 `parameterized` 可选模式，旧配置默认为 `fixed_notional`，不改变已存在的钱包、风格、预算或策略。新会话页面默认参数模式，可设置开仓保证金比例候选、加减仓比例候选、杠杆候选和最大杠杆。最大杠杆未指定时等于初始杠杆；10倍只是例子，现有2倍试验不能自行提高。

JEV Decisions 是 choice/noul/score 接口，不是任意文本 JSON 生成器。程序先生成完整候选方案，再用一次 choice 请求选择方案ID，避免分别判断金额和杠杆后拼出不一致指令。参考 [OpenRouter 官方教程](https://openrouter.ai/blog/tutorials/how-to-use-jev/)。

- 空仓：开多/开空，保证金预算 = 请求时净权益 × 比例；名义预算 = 保证金预算 × 杠杆。
- 持仓：只加同方向仓位；新增数量 = 请求时持仓数量 × 比例。减仓同样按数量，向合约数量步长取整；全平单独候选。
- 仓位不反转：反向交易先全平，下一轮再决定是否开反向仓位。
- 杠杆候选只来自配置且不超过硬上限。加仓时杠杆改变作用于整个逐仓仓位，不仅新增部分。减仓不改变杠杆。
- WAIT 不改变数量或杠杆。置信度不是胜率，不用于直接推算仓位。

数量、参考权益/数量/价格、比例基准、目标杠杆、候选ID以不可变 plan 保存到 cycle，转换成通用 TradeCommand。收到结果后不按新权益或新仓位重新解释百分比；版本变更、报价漂移、费用或资金不足拒绝执行。参数模式不得退回固定金额，也不得把部分减仓变成全平。

## 执行与兼容

通用 TradeCommand 添加可选目标杠杆；账户快照显示实际杠杆。Paper 在同一SQLite资金事务内完成保证金重算和成交，旧账本、命令指纹、查询重试兼容。已有资金费导致的保证金增减在变更杠杆时按保证金差额保留，不能用重算清除资金费。未知订单仍只查询，不重发。

杠杆下调需要补保证金时检查可用余额；杠杆提高释放保证金后仍检查强平边界、最大名义仓位、费用和亏损限制。Paper只是第一个执行后端；未来Testnet必须先确认交易所杠杆设置和实际保证金，再提交订单，不能声称已有Testnet支持。

独立调杠杆（不加仓）、止损/止盈、挂单类型和模型更新退出条件属于后续任务，本次不伪称完成。当前杠杆可随开仓/加仓变化，减仓和WAIT不改杠杆。模型暂停期间保留现有报价、资金费和清算维护。

## 验收范围

离线验证净权益20%/10倍开仓、现有数量加20%、减20%、全平、杠杆变更的现金守恒和越限拒绝，SQLite重启/同命令重试不重复成交。保留v1固定模式回归。展示模型选择与实际数量/杠杆，费用和风格记录继续沿用。无真实模型调用、交易所订单、安装依赖或试验钱包重配。

实际实现：每组比例/杠杆候选1–4个不重复整数，比例1–100、杠杆1–20；旧max_leverage缺省仍受原杠杆限制。v2问题集futures-plan-v2；choice最多255项、score仍最多10级。旧None字段不进入交易指纹；配置重试以首次配置审计为准，不恢复实际杠杆或充值。

证据：初始纯内核缺少杠杆上限的1项实际RED；首轮SQLite2失败/7通过（Mock仍action问题ID，和v2 plan不匹配），修复后相关121项通过/23.16秒。扩充多空、无可行方案0调用、>10候选与命令冲突后12项通过/3.95秒。配置重提1项RED，修复后最终参数/SQLite/执行52项通过/12.29秒。未跑全套。Ruff/format、JS语法和隔离HTTP页面/API200通过，模型调用0。首次OpenAPI检查发现公开入口本来禁用，保持禁用，仅检查内部schema。
