# JEV 持续等待、未产生交易的诊断讨论说明

整理日期：2026年10月10日。本文面向未参与项目开发的第三方，区分已确认事实与待验证假设。

## 1. 项目与预期行为

我正在开发一个 Binance USDT 永续合约交易助手，目前先运行本地模拟盘：使用真实公共行情和虚拟 USDT 钱包。

模型分工是：Claude Haiku 5.5 定期整理较长周期历史，JEV 独立读取背景摘要、即时行情和账户状态，决定开仓、加仓、减仓、平仓或等待，并选择仓位与杠杆。JEV 使用 OpenRouter 的 typesafe/jev-1.13，实际记录的供应商版本为 typesafe/jev-1.13-20260917。

会话风格由用户在0–100之间选择，0最保守、100最激进，资金及亏损上限始终生效。目标是让 JEV 对短线市场机会和持仓变化作出有效决策；模型调用频繁和成交次数多，本身都不是策略有效的证明。

## 2. 已确认的问题

RLC1（RLCUSDT）在北京时间2026年10月9日23:50至10月10日00:19的记录如下：

| 项目 | 实际结果 |
|---|---|
| 周期记录 | 497条 |
| 完整模型响应 | 475次，原始 choice 全部为 WAIT |
| 正常完成的等待 | 465次；另有10次完整返回受到时效等执行守卫拒绝 |
| 其余周期 | 22条没有完整模型响应，不能算作成功调用 |
| WAIT 选择概率 | 0.87–0.95，中位数0.91 |
| 模拟成交 | 0笔 |
| 模拟账户 | 空仓，权益1000 USDT |
| 风格 / 最低置信度 | 100 / 0.8 |
| 每次可选方案 | WAIT 加18个可行的开多、开空方案 |

475次响应具有475个独立供应商请求ID和475个不同输入hash，秒线窗口有472个不同hash。20根3分钟线和60根1秒线完整。输入不是一份静止行情，也不是本地反复显示同一个模型返回。

该窗口输入的标记价格从0.9189变为0.8511。价格变化说明市场状态确实变化，但不能据此认定某笔交易必然获利。

执行层从未收到开仓选择。因此，这批“没有交易”首先发生在模型选择层，不能解释为系统把开仓请求拦截后改成了 WAIT。最低置信度0.8对当前这些 WAIT 的选择不是一个能通过降低门槛直接解决的问题。

页面此前显示的6条档案均为空仓资金费结算，金额为0，已与成交分类显示。

## 3. 当前实际输入与输出

每次请求包含币种、USDT钱包与持仓、报价及资金费、风格、资金约束、策略要求、六层行情和预先计算好的交易方案。

| 信息层 | 送入 JEV 的形式 |
|---|---|
| 最近90天 | Haiku 对90根日线整理的摘要 |
| 最近30天 | Haiku 对180根4小时线整理的摘要 |
| 最近7天 | Haiku 对168根1小时线整理的摘要 |
| 最近1天 | Haiku 对288根5分钟线整理的摘要 |
| 最近1小时 | 20根3分钟线的完整 OHLCV |
| 最近1分钟 | 60根1秒线的完整 OHLCV |

前四层摘要包含趋势、价格依据与风险，默认15分钟有效并异步刷新。后两层提供开盘价、最高价、最低价、收盘价和成交量。

用户策略目前是一句通用要求：

> 根据当前行情和持仓选择开仓、加仓、减仓或等待，自主决定止盈止损时机；遵守资金、仓位和杠杆限额。

JEV 问题指令以“已有持仓时自主决定止盈止损时机”开头，之后要求选择完整交易方案、遵守限额，并明确“证据不足时选择 WAIT”。

输出是一个 Choice：选中的方案、各方案概率和置信度，不提供解释。例：最后一次完整响应选择 WAIT，WAIT概率0.90、置信度0.89。这里的0.90不是“市场有90%概率不动”，也不是交易胜率。

## 4. 需要探讨的三个具体问题

### 问题一：我们到底要求模型预测什么、优化什么？

目前有调用间隔、执行有效期，但没有明确的预测或预期持仓窗口。RLC1后来采用10秒调用间隔，结果执行有效期为3秒；这两个数值都不定义应该判断未来10秒、1分钟还是更长时间的走势。

空仓时的入场要求也没有与持仓管理分别定义。通用策略同时要求模型识别方向、选择机会、确定仓位与杠杆，并管理退出，却没有明确比较“现在开仓”和“继续等待”的标准。

**待验证假设：** 目标模糊，加上“证据不足则等待”的明确指令，使模型容易持续选择低承诺的 WAIT。这是设计上的疑点，还不是已证明的模型内部原因。

希望第三方回答：

- 如何定义短线决策的预测窗口与目标，区分发起频率、执行有效期和持仓时间？
- 空仓入场与持仓退出是否应分别提问？
- 如何把手续费、滑点及风险纳入开仓与等待的比较，同时保留合理等待的能力？

### 问题二：方向与仓位、杠杆是否不应合成一道大选择题？

当前请求要求在19个联合方案中选一个：

- WAIT。
- 开多9种组合、开空9种组合。
- 每个方向的组合是：5%权益保证金配1/2/5/10倍杠杆，10%配1/2/5倍，20%配1/2倍。其他组合被500 USDT名义仓位上限过滤。

例如 OPEN_LONG_M5_L2 表示用账户权益5%的保证金预算、2倍杠杆开多。数量由本地代码预先计算，JEV只选择可行方案。

**待验证假设：** 多个相近交易选项可能分散概率，让方向判断与参数选择互相干扰，而 WAIT 只有一个选项。

但当前 WAIT 已占87%–95%的总概率，不能仅靠把所有开多或开空概率相加，就声称解决了问题。

希望第三方回答：

- 应保留联合方案，还是拆成行动判断与给定方向条件下的参数选择？
- 如果分组，怎样保证方向、仓位和杠杆一致，且继续满足资金约束？
- 怎样解释新的置信度，并避免机械沿用目前0.8门槛？

JEV支持同一请求内独立回答多个问题，因此可以探索分组而不增加串行模型往返。但一个问题不能读取另一个问题的答案，条件问题必须在输入中写明，最终由代码校验组合。[官方 Choice 文档](https://docs.typesafe.ai/primitives/choice)

### 问题三：风格、长短周期证据和语言是否表达得不够清楚？

当前风格100被传入为 strength=100、aggression_weight=1.00、conservatism_weight=0.00，但没有明确说明它应如何改变机会容忍、信号确认要求或长短周期权重。

背景曾从“长周期看涨、短一些的周期横盘”变为“长周期看涨、7天和1天偏空”。JEV同时读取这些摘要与秒级行情，问题中没有明确规定短线判断时如何处理周期冲突。

此外，用户策略和 Haiku 摘要为中文，JEV问题指令为英文。厂商文档说明其主要训练语言为英文，CJK目前准确率较低；语言是值得对照的变量，而不是已经确认的故障原因。[官方 State 文档](https://docs.typesafe.ai/concepts/state)

希望第三方回答：

- 怎样把0–100风格转成清晰、可评测的决策偏好，同时保持硬风险上限？
- 长周期摘要应提供背景，还是能否决短线机会？冲突时如何处理？
- 是否应让 Haiku 给 JEV 输出英文或结构化背景，同时在用户页面保留中文？
- 中文与英文、不同周期权重，应该怎样独立比较效果？

## 5. 希望获得的建议与验证方式

希望第三方提供具体的请求设计、输出结构与评测方法，判断问题来自提问方式、数据组织、策略定义，还是 JEV 本身在这个任务上的能力限制。

建议以相同历史快照作对照，每次只改变一个因素，先记录模型选择，不执行订单。评估决策随市场状态的变化、概率分布、前后一致性及扣除交易成本的事后模拟结果，而不只统计有没有开始交易。

目前没有完成这些对照实验，没有证实上述某一因素是唯一根因，也没有验证 JEV 在此策略下的盈利能力。希望达到的是有效、可验证的短线决策，不以人为强制开仓或单纯降低风控门槛作为修复。

JEV官方说明它返回结构化判断与概率，不生成推理解释，因此我们需要通过输入对照和结果评测定位原因。[模型说明](https://docs.typesafe.ai/concepts/system-one)
