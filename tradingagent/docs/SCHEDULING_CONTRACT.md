# 决策调度契约

修订：2026-10-05。T08离线内核；尚未装配真实运行Supervisor或模型路由。

DecisionScheduler不调用模型；它把连续采样与低频评估分开。空仓300秒、持仓60秒，持有状态必须显式设置。周期与冷却使用ClockPort.monotonic，UTC仅用于事实和触发时间。墙钟回拨不延长已接收事件的排队期限。

普通事件按同类合并，30秒冷却，最多64条候选、256条去重缓存；重复ID内容不同拒绝，过期事件丢弃。只允许一个在途评估；complete必须提供当前trigger_id，失败的调用者也必须在finally释放。每次派发重新设置下次周期，避免定时和事件紧邻产生无意义的重复评估。队列超限淘汰最旧候选，不代表删除原始市场/成交事实；完整原始归档由T15负责。

hard_risk进入独立16条提醒队列，不等待在途评估、不预留或消耗模型预算。规则质量提醒与模型次数分开；它不会把硬风险事件自动升级为收费解释。

TriggerService仅在RUNNING会话生成事件。默认没有已验证的策略阈值，300条正常平静样本不会逐条触发模型事件。特征质量下降产生规则提醒；行情信号阈值需要显式值及policy_version，仅作为测试配置或后续已核实策略，不能由风格自动放宽硬纪律。风格原值/版本保留在会话及后续决策快照。

全局60次/小时由T03持久BudgetPort在真实收费请求预留时强制执行，手工与复盘共用该账本；Scheduler不另设重启就清零的计数。T11路由接入与全链路验证尚未实现，不能把触发次数等同收费调用次数或声称已联调真实模型。
