# JEV 多尺度输入方案（2026-10-09）

用户在2026-10-09确认调整为六层：前四层（90天、30天、7天、1天）在会话初始化时由背景LLM整理；原1小时与5分钟合并为20根3分钟K线；最后1分钟提供60根1秒K线。此决定取代此前七窗口与前五层背景整理方案。新建页面已默认六层，旧暂停会话可在工作区原位切换而保留钱包和档案。用户最新选定背景模型为OpenRouter Claude Haiku 5.5；正常AER页面/后台已真实验证四摘要＋20/60输入，无旧小时历史/30报价。实际请求、费用与限制见[JEV_MULTI_SCALE_RUNBOOK.md](JEV_MULTI_SCALE_RUNBOOK.md)。

## 背景LLM整理与JEV并行

会话初始化时预加载前四层历史；确定性代码先计算准确的涨跌、波动、量能和区间位置，再交给可配置的背景LLM形成结构化市场背景。当前背景模型为Haiku 5.5，与JEV独立；不扩展此前暂缓的常规Agent自动写监测脚本功能。

背景内容包含各层研判、关键价格区间、依据、失效条件、币种/市场、源数据hash、生成时间、数据截止时间与版本。原始事实及数值摘要保留，模型研判不能改写账户余额、现有仓位或资金纪律。首次有效摘要缓存后，后续JEV每次独立请求仍携带最新有效摘要，不能假设JEV记得初始化输入。

背景LLM默认每15分钟低频整理一次，频率可配置；本地各周期缓存按其收盘节奏更新。更新与JEV并行，不要求每轮等背景模型；新摘要校验通过后原子替换，失败不覆盖已有版本，过期或源身份不匹配不得伪装成当前有效背景。市场、币种、风格或模型改变时隔离旧摘要。Haiku与JEV使用各自核验的定价和同一累计费用账本，均已取得一次正常后台confirmed费用证据。

## K线边界与准备状态

本轮快照统一记录as_of，但各层单独记录实际起止与最新收盘时间。20根3分钟线截止于最近完整UTC三分钟边界，可能比当前报价早不足3分钟；当前价格仍由实时报价提供，不把未收盘K线混入这20根。60根1秒线截止于最近完整秒边界，必须连续且无重复。两组允许时间覆盖重叠，这是不同粒度的观测，不把成交量简单相加。

首次自动决策准备包括：20根真实3分钟线、有效背景摘要、60根完整秒线及有效实时报价。秒线优先接原生流；若没有可信的已保存秒线历史，启动需积累至少60秒，断线缺口不能补造。背景或秒线未准备好时显示具体缺项，不用收费JEV请求替代数据准备。上市不足90天时标记各背景层真实覆盖，由背景摘要明确说明；不能填造长期数据。

## 数据来源与边界

Binance USD-M公共REST `/fapi/v1/klines` 提供分钟及更长的原生历史K线，单页最多1500根。2026-10-09核对更正：此前将这个REST限制泛化为全部合约接口不支持1s，表述不准确。官方连续合约WebSocket的interval已列出1s，优先验证`{pair}_perpetual@continuousKline_1s`并直接缓存交易所秒线；连续合约REST历史接口仍最小列到1m，不能承诺秒线历史回补。此次代理ConnectError、直连ConnectTimeout，未实测秒线流。90天日线、30天4小时线、7天小时线各自可在单页范围内获取，但必须按已收盘边界校验连续性；上市不足90天时标记实际覆盖，不能补造。

`{symbol}@aggTrade`约100ms推送同价、同主动方聚合成交，包含交易ID、价格、数量、成交时间及maker标识，可独立用于更细主动成交统计；不作为接入秒线的默认前置工作。如后续确需本地聚合，必须标明`local_aggregation`及来源，不能冒充交易所原生K线。报价不等于成交，当前book/mark快照不能推导真实成交量、主动买卖量或完整盘口深度。

盘口不平衡、深度消耗等指标需新增partial/diff depth流并正确同步快照/更新ID；这个阶段单列，未接入时明确缺失。对丢帧、重连和冷启动保留`coverage_seconds`/gap/完整状态；没有成交的一秒只有在连续流覆盖可信时才能记成交量0，断线秒不能填0。不能从现有30条报价假定已有完整30秒或60秒数据。

官方资料：[Kline/Candlestick Data](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data#kline-candlestick-data)、[Continuous Contract Kline/Candlestick Streams](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/market#continuous-contract-kline-candlestick-streams)、[Aggregate Trade Streams](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/market#aggregate-trade-streams)。

## 缓存、输入密度和审计

1. 前四层历史及20根3分钟线启动时通过REST预加载，后续用WebSocket更新，分钟及更长周期断线后用REST补齐。缓存按symbol/market/interval/收盘边界隔离，每秒不重新HTTP下载历史。
2. 优先接原生1秒K线流，按pair/contractType/interval/open time增量更新、按closed状态确认；持久化交易所时间、接收时间、来源和缺口。若后续另接成交流，按aggregate trade ID去重、各自检查时效；只在完整数据已就绪后发布特征快照。
3. 一个`feature_snapshot`包含统一as_of、各层起止/覆盖/完整性、背景摘要版本和原数据hash；JEV只收四层背景摘要及固定20/60根短期序列，避免再发送旧七窗口原始历史。
4. 输入字节/token测量先行。现有样本约10364输入token，先消除可证明等价的重复字段，再增短线特征；输入体积目标待回放实测确定，不声称增加窗口自动提高准确率或降低推理耗时。
5. 背景LLM实际输入、输出、费用与来源证据独立归档；每次JEV完整实际输入、引用背景版本、特征版本和返回继续持久化，成交前后账户、方案、费用与原始行情继续同事务归档。缓存优化不能删除逐笔证据，也不能减少未知费用预留。

## 接续顺序

先实现20根3分钟线缓存，并免费验证原生1秒连续合约流，建立60根秒线缓存与准备状态；再实现前四层历史缓存、背景LLM配置/结构化整理/低频刷新和版本归档，最后装配到JEV输入。背景模型与JEV分别核对已配置的费用守卫；不默认增加成交流聚合或盘口深度，也不展开常规Agent脚本开发。以真实数据或有明确来源的录制数据验证周期、收盘状态和覆盖，不先用收费调用验证格式。框架验证后才在有效费用配置内作有界对照，比较输入token、端到端P50/P95、过期/跳过率；不承诺盈利效果或<500ms。

## 本轮已落地

每会话JEV分析间隔可选1–10秒，在新建第3步配置，或暂停后在JEV决策栏保存。其他会话不受影响；行情/资金费维护仍每秒，预测有效期仍3秒，不进行积压补发。

新真实调用的本地计时单独记录validation、reserve、provider、fee_validation、settle、binding和total（微秒），成功返回及有限失败诊断持久化、页面可展开。provider是模型适配器整个耗时，包括其内网络/远程/解析；网络Trace是嵌套分解，不可和provider重复相加。旧历史缺少新计时，保持原样，不回填猜测值。
