1.阅读论文 Bitcoin and Beyond: A Technical Survey on Decentralized Digital Currencies
1. BTC 到底是什么
BTC 不是一个存在你电脑里的“数字硬币文件”。更准确地说，它是 Bitcoin 网络账本中被共识认可的价值单位和所有权状态。论文也强调，比特币里并不存在独立的“coin 对象”，真正存在的是交易，以及交易形成的所有权关系。    Bitcoin_and_Beyond_A_Technical_…
你可以记成：
Bitcoin = 一套去中心化网络和协议
Blockchain = 它维护的分布式账本
BTC = 这套系统里的原生资产

2. BTC 为什么有价值
BTC 最初是系统奖励给矿工的资产，但“系统自己发”不代表没有价值。它后来获得市场价值，主要来自稀缺性、可验证性、可转让性、网络效应和市场接受度。
PoW 还给系统引入了真实成本：矿工要付出算力、电力、设备成本来维护账本。
3. BTC 数量有没有上限
有，理论最大供应量约 2100 万枚。
最初每个区块奖励 50 BTC，之后每 210,000 个区块减半：
50
→ 25
→ 12.5
→ 6.25
→ 3.125
→ ...

最终新区块补贴趋近于 0。论文对此有明确描述。    Bitcoin_and_Beyond_A_Technical_…
4. 山寨币和 BTC 有什么区别
BTC 是 Bitcoin 网络的原生资产。
其他加密货币可能：
Litecoin → LTC
Dogecoin → DOGE
Ethereum → ETH

它们的协议、区块链、共识规则、节点网络和历史都不同。
复制 Bitcoin 的代码，不等于复制 Bitcoin 的网络共识和历史，所以也不等于复制 BTC。
5. 区块是什么
你可以把区块理解成：
区块链账本的一页。

例如：
Block 100
Block 101
Block 102
...

区块数量会不断增加，区块高度也随之增加。
6. 一个区块被挖出后，还会继续往里面写吗
不会。
更准确地说：
先收集交易
↓
组成候选区块
↓
进行 PoW
↓
成功出块
↓
区块被接受
↓
这个区块基本定稿

新的交易会进入后续新区块。
所以不是：
先挖一个空区块
→ 再往里面写交易

而是：
先装交易
→ 再挖这个候选区块

7. 待确认交易会不会被篡改
可以被截获、延迟或者拒绝转发，但如果交易内容被改动，原来的数字签名就失效。
节点会检查：
签名是否合法
UTXO 是否存在
是否已被花费
有没有双花

所以“篡改后还能骗过网络”很难。
8. 交易手续费给谁
用户发交易时通常会支付手续费。
对于 UTXO 模型来说，手续费可以理解为：
输入总额 - 输出总额 = 手续费

这部分会归成功挖出该区块的矿工。论文也明确说明了这一点。    Bitcoin_and_Beyond_A_Technical_…
9. 以后没有新区块奖励怎么办
未来新区块补贴趋近 0 后，矿工主要依靠：
交易手续费

继续获得收入。
所以：
现在：
区块补贴 + 手续费

未来：
主要是手续费

10. 每个区块的数据量固定吗
不是固定值。
更准确地说是：
区块容量有限，但实际区块大小可以不同。

不同交易大小也不同，所以每个区块包含的交易笔数也不同。
论文在当时版本里讨论了 Bitcoin 区块大小上限及扩展性问题。
11. 矿工是分布式的，那怎么收集交易
每个矿工/矿池都独立接收 P2P 网络传播来的交易，放到自己的 mempool，然后自己选择交易组成候选区块。
所以不同矿工的候选区块可能不同：
矿工A：
交易1、2、3

矿工B：
交易1、4、5

谁先完成 PoW，谁先广播自己的区块。
12. 如果两个矿工同时挖出区块呢
可能短暂形成分叉：
          → 101A
Block100
          → 101B

不同节点短时间内可能接受不同分支。
之后哪条链累计工作量更高，就更可能成为主链。
13. 同一笔交易会不会出现在两个区块
会，短时间内有可能。
例如：
101A：包含交易X
101B：也包含交易X

最终只有主链中的那一份算正式确认。
14. 101B 被淘汰后，里面独有的交易会不会丢
通常不会直接丢。
如果交易：
没有冲突
+
没有已经在主链确认

通常会重新变成未确认交易，等待后续区块重新打包。
如果和主链冲突，比如花了已经被主链花掉的同一个 UTXO，那就会失效。
15. 交易暂时处于孤块/陈旧块中，会有问题吗
会带来短暂不确定性。
比如一笔交易刚进入区块，但这个区块后来被淘汰，那么交易可能又回到“未确认”。
这就是为什么会有：
1 confirmation
2 confirmations
3 confirmations
...

确认数越多，一般越稳固。论文提到经典经验是等待多个确认，常见参考值为 6 个。    Bitcoin_and_Beyond_A_Technical_…
16. 如果在不稳固的时候交易 BTC 怎么办
如果只是普通转账，区块被回滚后，交易往往只是重新等待确认。
但如果你已经：
收到 BTC
↓
马上交付商品 / 现金 / 其他不可逆资产

那风险更大。
所以原则是：
金额越大、对方越不可信、交付越不可逆，就应该等更多确认。

17. Bitcoin Network 那个模型怎么理解
你可以按四层理解：
第一层：通信
P2P 网络

第二层：数据
交易 + UTXO + 区块链

第三层：安全与共识
公私钥 + 数字签名 + PoW

第四层：经济
区块奖励 + 手续费 + BTC

分别解决：
P2P
→ 消息怎么传

交易 / UTXO
→ 钱怎么表示和转移

区块链
→ 历史账本怎么保存

私钥 / 签名
→ 谁有权花这笔钱

PoW
→ 冲突时谁有资格写下一页账本

经济激励
→ 为什么有人愿意长期维护系统

18. “PoW 竞争记账权”是不是就是比谁先挖出区块
对。
更准确地说：
组装候选区块
↓
不断尝试 nonce
↓
计算 hash
↓
直到 hash < target
↓
成功出块

所以：
PoW 竞争记账权 = 竞争谁先找到一个有效候选区块。

19. nonce 是什么
nonce 可以理解成矿工反复改变的一个数字。
矿工不断试：
nonce = 1
nonce = 2
nonce = 3
...

每次重新计算区块哈希。
直到：
hash < target

这个区块就满足 PoW 条件。
20. “哈希满足难度目标”是什么意思
SHA-256 会产生一个 256 位结果，可以把它看成一个超大整数。
系统规定：
hash < target

才算合法。
target 越小，符合条件的 hash 越少，因此越难挖。
21. SHA-256 是什么
SHA-256 是一种密码学哈希函数：
任意长度输入
↓
SHA-256
↓
固定 256 bit 输出

特点：
- 同样输入 → 同样输出
- 输入稍改 → 输出大变
- 很难反推输入
- 很难找碰撞
- 输出看起来近似随机
Bitcoin 挖矿实际使用的是对区块头进行双 SHA-256。
22. SHA-256 的规则是不是公开的
完全公开。
矿工知道：
SHA-256 算法
target
区块内容

不知道的是：
哪个 nonce 会碰巧得到 hash < target

因此只能大量尝试。
23. 能不能把 SHA-256 所有情况都提前记录下来
理论思想类似预计算表，但实际上不可行。
SHA-256 输出空间：
2^{256}
约为：
1.16\times10^{77}
而且输入空间并不只有 \(2^{256}\)，因为 SHA-256 支持任意长度输入。
更重要的是 Bitcoin 区块内容持续变化：
previousHash
交易集合
Merkle Root
timestamp
extraNonce

这些一变，nonce 对应的 hash 就全部重新洗牌。
所以预计算表几乎没有实用意义。
24. 能不能用算法让 SHA-256 逐渐变小
目前没有已知的实用算法可以做到。
SHA-256 没有：
“往这个方向调，hash 就会越来越小”

这种梯度。
更像：
每改一次输入
→ 重新随机抽一个 256 位数字

所以矿工不是“优化 hash”，而是：
不断重新抽样，直到碰到一个足够小的 hash。

25. SHA-256 如果被攻破，BTC 会不会完蛋
要看“攻破”的程度。
如果只是出现部分碰撞弱点，不一定马上致命。
但如果有人能：
不靠大量试 nonce
↓
快速定向找到满足 hash < target 的输入

那 PoW 的安全基础就会严重受损。
不过 Bitcoin 协议理论上可以通过升级更换 PoW 哈希算法，所以不一定意味着瞬间归零。
